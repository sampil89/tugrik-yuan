# Tugrik Yuan — сайт (этап 2: база данных и серверная авторизация)

Vite + React + serverless-функции Vercel + Postgres. Шапка, hero с формой
заявки, живой курс валют, футер и админ-панель (курс валют вручную,
заявки, новости, объявления). Все данные теперь общие для всех
посетителей и хранятся в базе, а не в браузере одного человека.

## Настройка базы данных (один раз)

Отдельного продукта «Vercel Postgres» больше нет — с конца 2024 года базы
подключаются через **Vercel Marketplace**, обычно это провайдер **Neon**
(бесплатного плана с запасом хватает для такого сайта).

1. В дашборде Vercel, в проекте — вкладка **Storage → Create Database**
   (или «Connect Database»). Выбрать **Postgres**, затем провайдера
   **Neon** (Vercel-Managed Integration — самый простой вариант, не
   нужен отдельный аккаунт на neon.tech).
2. После подключения Vercel сам добавит переменную `DATABASE_URL`
   (и обычно ещё `POSTGRES_URL` для обратной совместимости) в настройки
   проекта — вписывать вручную ничего не нужно.
3. Выполнить `schema.sql` в новой базе. Обычно это делается через
   вкладку **Query** / **SQL Editor** в дашборде базы (если у вашего
   провайдера в дашборде Vercel её нет — можно открыть базу в родном
   интерфейсе Neon по ссылке из карточки Storage).
4. В настройках проекта на Vercel → **Settings → Environment Variables**
   добавить:
   - `ADMIN_PASSWORD` — пароль для входа в админку (уже не в коде).
   - `ADMIN_SESSION_SECRET` — любая случайная строка подлиннее (нужна для
     подписи cookie-сессии администратора).

## Локальный запуск

Нужен Node.js 18+ и CLI `vercel` (`npm i -g vercel`).

```bash
npm install
vercel link          # один раз — свяжет папку с проектом на Vercel
vercel env pull .env.local
npm run dev:full      # запускает и фронтенд, и /api-функции вместе
```

Обычный `npm run dev` (просто Vite) поднимет только фронтенд — админка и
формы работать не будут, потому что `/api`-функции выполняет именно
`vercel dev`. Для чистой вёрстки без бэкенда `npm run dev` подходит,
для полноценной проверки — `npm run dev:full`.

Сборка для продакшена: `npm run build`.

## Как устроено

- `src/App.jsx` — компоненты сайта (Header, Hero, ApplicationForm,
  CurrencyBoard, Footer, AdminLoginModal, AdminPanel). По мере роста
  стоит разнести на отдельные файлы в `src/components/`.
- `api/` — serverless-функции (каждый файл = один эндпоинт):
  - `rates.js` — курс валют (GET публично, PUT только для админа).
  - `leads.js` — заявки с формы (POST публично с honeypot-защитой,
    GET только для админа).
  - `news.js`, `announcements.js` — новости и объявления (GET
    публично, POST/DELETE только для админа). Публичного вывода на
    страницу пока нет — это задел на следующий этап.
  - `admin/login.js`, `logout.js`, `session.js` — вход по паролю из
    переменной окружения `ADMIN_PASSWORD`, сессия — в httpOnly cookie,
    подписанной `ADMIN_SESSION_SECRET`. Пароль никогда не попадает в
    браузер и не хранится в коде фронтенда.
  - `lib/db.js`, `lib/auth.js` — общие утилиты (клиент Postgres,
    проверка cookie-сессии).
- Курс валют тянется с публичного `open.er-api.com` (база MNT),
  автообновление раз в 30 минут; резервные значения — в
  `FALLBACK_RATES` в начале `App.jsx`.
